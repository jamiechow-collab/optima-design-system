## Overview

Text areas let users enter and edit multiple lines of free text — longer-form content than a
single-line text input, such as comments, descriptions, or messages.

## Anatomy

<Unstyled>
  <AnatomyExample />
</Unstyled>

A text area is made up of a field title, an optional tooltip, a field container, and optional
helper or validation text (with an optional character counter) underneath. Drag from the
bottom-right corner to resize the field vertically.

- Placeholder text, helper text, tooltips, and the counter are all optional for Text Area.
- If there is a limit, the counter has to display to acknowledge users about the limit.
- If we allow users to adjust the container height, include a dragger to indicate that ability.

## Types

There are three validation types. Always use Default — only switch to Error validation when
feedback needs to be shown for a failed validation. Success validation's use case is still TBD.

## States

All types of text field have an Empty and a Filled state. Empty is when there is no entry, Filled
is when an entry has been submitted. Within each, the field can be Default, Hover, Active,
Focused, Disabled, or (once filled) Read only.

**Active** — triggered by clicking into the field with a mouse; the caret appears and the border
darkens, with no focus ring. **Focused** — triggered by moving focus with the keyboard (e.g.
**Tab**); the border darkens and a focus ring appears, so keyboard users can always see where
focus is.

## Interactions

**Mouse** — Users press the field container to start typing. When they click elsewhere on the
interface, the field goes back to its default state.

**Keyboard** — Users can press **Tab** to bring focus to the text area.

**Enter** or **Space** opens any associated actions added to the input. **Esc** closes any
associated actions added to the input.

**Opt + up/down arrows** relocates the caret to the start or end of the input content.
